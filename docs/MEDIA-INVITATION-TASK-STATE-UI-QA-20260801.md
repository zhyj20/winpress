# 媒体邀请任务状态界面 QA（2026-08-01）

## 结论

`/tasks` 的媒体邀请处理弹窗现只展示服务端状态机允许的下一步。未登记实际邀请时，运营人员不能在界面跳过邀请直接记录回复、到场或成果；媒体邀请已结束时，沟通状态与成果回填入口均锁定。本轮只收紧平台内的事实记录，不表示任何媒体已经受邀、到场、采访或报道。

## 发现的问题

服务端已通过 `WorkflowService.canAdvanceMediaInvitation()` 限制邀请状态，但 `TasksView.vue` 曾在任意可处理媒体任务中列出全部沟通状态，并始终显示成果回填表单。错误选择会被接口拒绝，却让执行人员先看到不存在的操作路径；未发出邀请时也会出现不应使用的成果入口。

## 修复

- `PENDING`：只可登记“已发出邀请”或“不再继续”；
- `INVITED`：只可登记回复、到场、婉拒或不再继续；
- `RESPONDED`：只可登记到场、婉拒或不再继续；
- `ATTENDING`：只可登记不再继续；
- `DECLINED`、`NOT_PROCEEDING` 和已完成记录不再显示可修改的沟通表单；
- `MEDIA_PR` 任务只有在 `INVITED`、`RESPONDED` 或 `ATTENDING` 时显示成果回填。待发邀请和已结束邀请均显示原因说明，而不是提交后再由接口报错。

后端状态机、行锁、事实说明必填、成果链接核验和客户字段隔离未改变，仍是最终约束。
