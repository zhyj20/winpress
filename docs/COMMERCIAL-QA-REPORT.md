# WinPress V4.1 商用交付自检报告

> 历史归档（非当前验收基准）。本文是 V4.1 阶段性回归记录，不用于证明当前源码、第三方检索授权、供应商履约、法律信息或生产部署已经验收。当前验收以 [`PRODUCT-PRD-V4.2.md`](PRODUCT-PRD-V4.2.md)、[`WINPRESS-GLOBAL-PRODUCT-CODE-AUDIT-20260728.md`](WINPRESS-GLOBAL-PRODUCT-CODE-AUDIT-20260728.md) 与 [`P0-P1-EXECUTION-QA-20260728.md`](P0-P1-EXECUTION-QA-20260728.md) 为准。

检查日期：2026-07-23。

## 验收结论

V4.1 已把云发布整理为以项目为中心的新闻传播执行系统。原有媒体邀请平台完整保留；云采写支持按 980 元/人/天下单、平台就近匹配写手并由写手接单；直编发稿先保存计划、客户确认后再生成任务；新闻发布会新建项目生成 9 项执行清单。成本与客户服务价在平台运营端分列、可人工调整并留痕，对客接口继续隐藏成本、供应商和上游来源。

当前验收环境分为两部分：本机存量数据库 `55432` 已执行 V4.1 结构迁移；8092 后端连接隔离质检库 `55433` 和 Redis `6381` 完成业务回归。由于存量库历史凭据与当前编排配置不一致，本报告不把“8092 已连接存量库”列为通过项。

## V4.1 新增闭环

- 发布计划采用两阶段提交：保存计划只生成 `WAITING_CONFIRMATION` 记录；客户确认后才生成发布任务。
- 同一计划重复确认返回同一任务，不重复下单。
- 普通媒体邀请可与直编发稿并行；只有显式排他邀约才建立指定稿件版本、带截止时间的锁。
- 普通媒体邀请可从活动简报直接创建，不强制要求已有定稿；直编发稿和排他媒体邀约仍须绑定客户已确认的稿件版本。
- 云采写订单生成待匹配派单；平台运营选择可用写手发出任务，写手可接单或拒单，价格和金额按 980 元/人/天保存快照。
- 新闻发布会由 5 项粗清单升级为 9 项可执行清单，覆盖范围、议程、场地、材料、拟邀、邀请、现场、会后发布和复盘。
- 直编渠道商品与媒体主体、报价记录分离；平台运营可同时维护成本价和客户服务价，系统禁止客户服务价低于成本价。
- 客户任务列表不显示供应商归属，统一显示云发布项目执行归口。

## 已修复问题

- 前端重构为 Vue 3、Vite 和 TypeScript，统一路由、会话、接口错误、加载状态、空状态与成功反馈。
- 后端重构为 Java 17 和 Spring Boot 3，统一返回结构、参数校验、异常处理、角色权限与操作日志。
- 登录会话写入 Redis；账号停用或角色变更后，原会话立即失效。
- 客户、服务运营和平台运营按组织、项目归属和任务分配范围查询数据。
- 云采写支持写手按客户委托到场采集事实素材、撰写和修改稿件；写手不以媒体记者身份到场，也不参与媒体邀请或决定媒体发布。
- 云采写单价由后端固定为 980 元/人/天，订单保存人数、天数、基础金额、现场联系人、交付要求和就近优先规则。
- 媒体邀请仍为独立服务，支持与云采写组合下单，但媒体邀请、交通住宿、摄影摄像和额外稿件不混入采写基础价。
- 只有双方明确约定的排他媒体邀约才启用限时稿件锁；锁有效期内，同一稿件版本不能提交新的直编发稿计划。
- 新闻发布会新建项目自动生成 9 项统筹清单；服务运营与平台运营可在项目内更新进度。旧演示项目原有 5 项清单作为历史数据保留。
- 媒体邀请与直编发稿任务独立记录，并统一回填成果、监测和客户验收状态。
- 客户渠道接口采用字段白名单，不返回成本、来源、供应商标识和内部备注。
- 运营端可新增渠道，并可调整现有渠道资料、内部成本、客户服务价、报价有效期和可用状态；改价生成新报价，历史订单保留原报价引用。
- 媒体公开字段已清理原始枚举、乱码和保证性表述；待复核媒体不进入客户可选清单。
- Docker 数据库初始化顺序固定为建表、基础种子、品牌案例、媒体导入和公开字段规范化。
- 桌面端与移动端修复了整页溢出、窄列逐字换行和操作区拥挤问题。
