# 传播看板角色与指标闭环 QA（2026-07-31）

验收范围：本机 Docker 演示环境的 `/dashboard`、管理员咨询列表 `/admin/inquiries`，以及由看板指标跳转的既有任务、项目与订单列表。本记录仅说明本机页面、接口口径和权限投影；不代表外部媒体数据、供应商履约、牛媒来源工单、支付、法律主体或生产环境已经验收。

## PRD 对齐

- 看板按角色呈现“待我处理、进行中项目、待客户确认、待平台执行、任务记录、已完成待验收 / 待客户验收”等可操作口径；
- 四项独立服务使用“邀请媒体、直编发稿、云采写、举办新闻发布会”作为统计和入口名称；
- 每张指标卡的数字必须与落地列表使用相同的筛选条件；字段缺失时显示“数据暂不可用”，不得以零代替；
- 无可核验来源标识的普通咨询只能称为“商务咨询”，不能因系统上下文、客户名称或演示数据被称为“牛媒信源工单”。

## 本轮发现与修复

1. 管理员看板的“待处理咨询”卡片已链接到 `/admin/inquiries?status=NEW`，但咨询页原先没有读取路由参数，造成卡片数字与落地列表筛选不一致。
   - 修复：咨询页现在校验并应用 `status`、`type`、`page` 查询参数，路由查询变化时重新加载；`NEW` 卡片会真实请求并显示“待联系”范围。
2. 看板四项服务统计仍有一处旧名称“新闻发布会”。
   - 修复：统一为正式服务名称“举办新闻发布会”。
3. 客户看板有六项主指标，但桌面端固定五列，导致最后一张卡片孤立到第二行；移动端运营和管理员有五项指标，最后一张卡片也显得悬空。
   - 修复：客户桌面端采用六列完整一行；`920px` 以下回落为三列，`760px` 以下回落为两列；运营和管理员在移动端把第五张卡片跨满最后一行。

## 外部来源边界

- 当前 `business_inquiry` 仅保存咨询类型、企业、联系人、联系方式、内容和处理状态，不保存可核验的外部来源标识；
- 因此管理员看板只提供“待处理咨询”入口，工作项也使用“商务咨询”标签；本轮没有新增虚构的外部来源数据、来源名称或联动状态；
- 真正展示“牛媒信源工单”前，必须先完成来源标识字段、逐条验签/可追溯证据、最小权限投影、授权范围和联调验收，并把其列表和数字放在同一受控查询中。
