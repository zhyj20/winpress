# 直编发稿成果回填履约门禁 QA（2026-08-01）

## 结论

直编发稿任务的成果回填入口已与服务端履约门禁一致。运营人员只有在平台内确认该任务可回填后才会看到表单；客户接口不返回这一内部准备状态，也不会暴露供应商、成本、上游订单号或履约凭据内容。

## 问题与影响

`WorkflowService` 已要求：当直编任务绑定供应商后，对应订单必须为已完成，履约方式为人工或 API，且已登记非空凭据引用，才能回填成果。旧版 `TasksView` 没有读取这个条件，始终显示成果回填表单。结果是用户能够进入一个后端必然拒绝的操作路径。

## 修复范围

- 任务查询在运营／管理员范围增加 `resultReady` 状态：
  - 未绑定供应商：可由平台继续登记成果；
  - 已绑定供应商：仅在完成、履约方式合格且有凭据引用后可回填。
- 前端仅在 `resultReady !== false` 时显示直编成果回填；未就绪时显示“履约核验尚未完成”的说明。
- `MEDIA_PR` 仍使用其独立的邀请事实状态机，不受本次直编门禁影响。
- 客户任务、客户任务详情和客户字段边界中均不返回 `resultReady`。

## 边界与后续

- `resultReady` 只反映平台内部是否满足成果登记前提，不表示供应商已真实履约，也不表示外部渠道已发布。
- 外部供应商的真实下单、报价、回执、对账、重试和服务等级，仍须逐家授权、字段映射、沙箱联调和验收记录。
- 本轮 Docker Hub 无法获取 Nginx 基础镜像的认证令牌，故新前端镜像的完整重建仍待网络恢复后复验；本轮仅使用临时静态构建注入现有本机 Nginx 容器验证页面与响应头。
