## 1. 本轮解决的问题

旧版本把官网文案、服务介绍和后台对象混在一起，客户能看到很多解释，却不容易判断下一步；发布计划一提交就生成任务，缺少正式确认；云采写有下单价格但没有完整派单记录；媒体邀请与直编发稿被一概互斥；成本价虽然存在，却没有完整的人工调价与历史对照。

V4.1 按“传播项目—服务需求—确认方案—执行任务—成果验收”重建产品主线。云采写、媒体邀请、直编发稿和新闻发布会保留各自规则，通过项目协作而不是文案拼接形成组合服务。

## 3. 数据库变化

新增 `service_price_book`、`writer_profile`、`writing_assignment`、`media_outlet`、`media_contact`、`publish_offering`、`publish_plan`、`publish_plan_item`。同时为发布任务增加计划项来源，为稿件锁增加版本和到期时间，为调价记录增加成本变化字段。

当前全新数据库为 40 张业务表。核心扩展依次执行迁移 11 至 14，覆盖产品核心、普通媒体邀请无稿件起单、发布会渐进建项、供应商订单与商务咨询。

## 5. 验收证据

- 后端单元与集成测试：20 项通过，0 失败、0 错误。
- 前端生产构建：Vue TypeScript 与 Vite 构建通过。
- API：健康检查和 Swagger 可访问。
- 发布计划：草稿不生成任务；确认生成任务；重复确认不重复生成。
- 媒体邀请：普通邀请可不带稿件保存和确认；直编发稿、排他邀请仍校验已确认稿件。
- 云采写：订单、派单、接单、980 元价格与金额快照通过实际接口验证。
- 定价：成本价和客户服务价调整、历史记录与字段隔离通过实际接口验证。
- 数据：隔离质检库加载 22,783 个直编渠道和对应对客渠道商品。
- 媒体筛选：分类字典返回媒体类型 10 项、媒体形态 26 项、地区 36 项；媒体邀请双候选计划和发布会双候选批量加入均通过实际接口验证。

详细记录见 `COMMERCIAL-QA-REPORT.md`。

## 6. 明确未冒充完成的外部能力

- 牛媒媒体与记者搜索路径、字段适配、分类字典、缓存、限额处理和人工候选兜底已实现；文档未提供正式 Token，生产授权、商业额度和数据许可仍待复验。
- 站外传播监测采集器尚未接入；当前支持成果链接和核验记录。
- 支付网关、电子发票、短信和对象存储需要生产服务商配置。
- API 接入不接受普通项目下单。面向第三方租户的商务评估、密钥签发、限流、回调签名和开放门户属于后续独立能力，不在本轮验收范围。
- V4.1 由 `writer_profile` 区分可接单的服务运营账号；若未来开放大规模外部写手入驻，应再增加独立 `WRITER` 角色、实名审核、结算和隐私授权，不在现有三角色模型中假装已经完成。

## 7. 运行边界

当前独立 Docker 栈使用前端 `5217`、后端 `8192`、PostgreSQL `55434` 和 Redis `6382`，未接管历史 `55432` 数据库。生产切换前仍须统一正式凭据并执行备份恢复和角色流程验收。
