# 开放 API 整合验收记录（2026-07-30）

## 验收结论

此前单独开发的 API 工具已作为云发布的受控客户系统接入模块整合到现有 Vue 3／Spring Boot／PostgreSQL 架构。接入系统创建的服务需求不再落入独立业务库，而是调用既有 `WorkflowService`，进入客户需求、项目、任务与订单记录链路。

本次本机验收通过。它仅证明本机演示环境的代码、数据库和接口闭环，不代表任何外部媒体数据、供应商履约或生产凭据已经验收。

## 纳入范围

| 能力 | 当前实现 | 业务边界 |
|---|---|---|
| 接入应用 | 平台管理员登记客户归属、范围、环境、限流及验收状态 | 未完成授权与沙箱验收不能启用；生产还需生产批准 |
| 访问密钥 | 一次性签发，数据库仅保存 SHA-256 摘要与前缀 | 原始密钥不写入数据库、页面或请求日志 |
| 服务目录 | 提供四项独立服务的可受理目录 | 不创建组合服务 |
| 直编渠道目录 | 复用云发布对客字段投影与筛选字典 | 仅供参考；不构成库存、排期、价格或履约承诺 |
| 服务受理 | 通过现有工作流创建需求和项目 | 仅限应用绑定客户；回执按应用隔离 |
| 请求留痕 | 保存操作、状态、耗时与请求摘要哈希 | 不保存请求正文、供应商、成本、上游字段或密钥 |

开放 API 管理入口：`/admin/open-api`。内部供应商接口配置仍位于 `/admin/integrations`，两者的权限、密钥和履约边界互不混用。

## 本轮发现并修复

首次闭环时，“新增接入应用”返回 500。原因是 PostgreSQL 的 `RETURN_GENERATED_KEYS` 返回了完整插入行，`GeneratedKeyHolder.getKey()` 只能接受单一返回列。`OpenApiRepository` 已改为从生成键映射中明确读取 `id`，并重新完成应用登记、签发、调用、撤销与暂停回归。

另外，开放 API 限流已使用 Redis 固定窗口计数，以便多应用实例共享限额；Redis 短暂不可用时保留受限的进程内兜底，避免静默放开接口入口。

限流拒绝本身也会写入脱敏访问摘要，便于运营核验异常突发调用；该记录不含访问密钥、请求正文或客户业务内容。
