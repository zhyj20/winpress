# 媒体与发布任务角色与状态筛选 QA（2026-07-31）

验收范围：本机 Docker 演示环境的 `/tasks`，覆盖客户、服务运营、平台运营三种角色的任务列表投影、负责人安排入口，以及终态任务的深链筛选。本文只记录当前源码和本机运行结果；不代表任何外部媒体、供应商、支付或生产环境能力已经验收。

## PRD 对齐

- `PRODUCT-PRD-V4.2.md` 将“媒体与发布任务”定位为媒体邀请与直编发稿的当前执行任务；云采写仍由独立的“云采写任务”处理。
- 客户只看本组织可核验的公开字段；运营人员只处理已分配任务；平台运营负责安排负责人及全局异常处理。
- “暂不推进”是已发生的终态记录，不能因前端筛选器遗漏而从可追溯任务视图中消失。

## 问题与根因

`/tasks?status=NOT_PROCEEDING` 的后端查询和状态标签均支持 `NOT_PROCEEDING`，但 `TasksView.vue` 的路由白名单未包含该状态。页面加载时把有效的 URL 条件重置为空，导致管理员无法通过深链回看已终止的媒体邀请或发布任务。

在修复前新增的 Playwright 用例于桌面和移动端均稳定失败：状态选择框预期为 `NOT_PROCEEDING`，实际为空值。

## 已实施修复

1. 将 `NOT_PROCEEDING` 加入 `applyRouteFilters()` 的允许状态集合；
2. 在“按任务状态筛选”中加入客户可理解的“暂不推进”选项；
3. 新增桌面与移动端回归：访问 `/tasks?status=NOT_PROCEEDING` 后，筛选条件必须保持，且页面没有横向溢出、资源缺失或控制台错误。

## 权限与数据边界复核

- 客户列表不返回内部主键、负责人、执行说明或异常原因；
- 运营人员不能看到未分配任务，也不能处理未获授权的项目；
- 平台运营对待分配任务仅显示“安排负责人”入口，跳转至项目级负责人安排，不把任务状态伪造为已执行；
- 终态筛选仅恢复已有任务的可查性，不改变状态机、不写入数据库、不创建订单，也不改变外部履约事实。
