# 云发布产品需求文档 V4.1

状态：历史阶段基线（非当前验收基准；当前以 `PRODUCT-PRD-V4.2.md` 为准）  
生效日期：2026-07-23  
适用范围：官网、客户工作台、服务执行台、平台运营台、数据库与 API

> 本文仅保留 V4.1 的决策与追溯信息。当前四项独立服务、客户数据边界、外部能力待确认规则及商用门槛以 [`PRODUCT-PRD-V4.2.md`](PRODUCT-PRD-V4.2.md) 和 [`WINPRESS-GLOBAL-PRODUCT-CODE-AUDIT-20260728.md`](WINPRESS-GLOBAL-PRODUCT-CODE-AUDIT-20260728.md) 为准。

## 1. 产品定义

云发布面向企业新闻传播项目，管理现场采写、媒体邀请、直编发稿和新闻发布会的执行过程。API 接入作为企业级合作能力单独评估，不进入日常服务下单。

产品不要求客户从同一个起点进入。客户可以已经有稿，也可以只有活动、事实材料、媒体邀请需求或系统接入需求。

## 2. 产品边界

### 2.1 云发布提供

- 云采写：平台写手完成事实与素材采集、资料梳理、稿件撰写和约定修改。
- 媒体邀请：围绕活动或新闻议题筛选媒体、发起邀约、记录反馈和现场协调。
- 直编发稿：针对已有定稿，按客户服务价、时效和发布要求选择渠道并提交执行。
- 新闻发布会：管理主题、议程、嘉宾、场地、媒体、现场内容和会后传播。
- API 接入咨询：评估客户自有系统的字段、鉴权、媒体范围、价格规则和结果回传，不作为普通服务订单。

### 2.2 云发布不提供的承诺

- 不把平台写手包装成受邀媒体记者。
- 不承诺媒体必到场、必采访、必报道或必收录。
- 不在客户页面公开供应商、原始接口来源、采购成本、密钥或内部账号。
- 不把牛媒信源 GEO 的自控渠道治理功能并入云发布。
- 不用未经授权的品牌名称和虚构数据冒充客户案例。

## 3. 客户进入方式

| 客户现状 | 首选入口 | 最小必填信息 | 核心交付 |
|---|---|---|---|
| 尚无成稿，需要现场或远程写作 | 云采写 | 时间、地点、事实、联系人、用途 | 初稿、修改记录、定稿 |
| 有活动，希望邀请媒体 | 媒体邀请 | 活动信息、新闻点、媒体方向、联系人 | 邀请名单、沟通状态、反馈记录 |
| 已有定稿，需要发布 | 直编发稿 | 定稿版本、渠道选择、预算与排期 | 发布任务、链接、异常与替换记录 |
| 要举办重要活动 | 新闻发布会 | 标题、联系人、联系电话 | 项目清单；其他活动资料按阶段补充 |
| 自有系统需要媒体能力 | API 接入咨询 | 商务联系人与初步对接场景 | 评估结论、接口方案、联调计划 |

四项日常服务分别下单并创建传播项目。客户可在同一活动中分别购买多个服务，但每项服务保留独立的准入条件、执行状态、费用和结果边界，不创建“现场采写＋媒体邀请”组合订单类型。

## 4. 核心业务对象

### 4.1 项目层

- `project`：一次传播工作的统一容器。
- `customer_requirement`：客户提交的事实、目标、时间和服务意向。
- `customer_requirement` 及各专业子对象共同表达项目中的服务订单；V4.1 不另设一张没有业务行为的通用 `service_order` 表。
- `file_asset`：项目材料、图片、附件和交付文件。

### 4.2 内容层

- `editorial_task`：内容采写任务。
- `writer_profile`：写手能力、服务区域、档期和状态。
- `writing_assignment`：写手派单、接单、拒单、价格快照和履约状态。
- `manuscript` / `manuscript_version`：稿件及可追踪版本。

### 4.3 传播层

- `media_outlet`：媒体机构或品牌。
- `media_contact`：记者、编辑或媒体联系人，仅限授权角色使用。
- `publish_offering`：可购买的直编发布产品。
- `conference_media_candidate`：发布会拟邀媒体与邀请进度。
- `media_pr_invitation`：已生成媒体邀请任务的对象与回复状态。
- `publish_plan` / `publish_plan_item`：客户确认前的传播方案、预算和价格快照。
- `publish_task`：方案确认后拆分的执行任务。

### 4.4 发布会与交付层

- `conference_project`：发布会项目属性。
- `conference_work_item`：议题、议程、嘉宾、场地、媒体、现场与会后任务。
- `result_link`：报道或发布结果。
- `monitoring_record`：经核验的后续状态。
- `settlement_order`：项目结算与开票。

### 4.5 供应商与商务线索层

- `supplier` / `supplier_channel`：平台内部维护的执行服务商及其可执行渠道，不向客户公开。
- `supplier_order` / `supplier_order_status_history`：客户确认发布计划后生成的上游执行订单及状态留痕。
- `business_inquiry`：官网服务咨询、API 接入和商务合作线索；不等同于传播项目或服务订单。

## 5. 主流程

```text
选择任务入口
→ 创建传播项目
→ 补齐该服务的最小信息
→ 需要时另行添加其他服务
→ 生成方案、报价与排期
→ 客户确认
→ 系统拆分执行任务
→ 执行、反馈与异常处理
→ 成果回填
→ 客户验收
→ 结算与归档
```

### 5.1 发布计划流程

```text
已确认稿件版本
→ 选择直编渠道或媒体邀请目标
→ 保存发布计划草稿
→ 锁定渠道、报价和稿件版本快照
→ 展示预算、规则、排期与风险
→ 客户确认计划
→ 创建发布任务
→ 执行与结果回填
```

保存草稿不得创建发布任务。只有客户明确确认后，计划才能进入执行状态并拆分任务。重复确认必须幂等，不得生成重复任务。

### 5.2 云采写流程

```text
客户下单
→ 记录 980 元/人/天价格快照
→ 按地点、档期与领域筛选写手
→ 发出派单
→ 写手接单或拒单
→ 到场或远程采集事实与素材
→ 提交初稿
→ 客户修改与定稿
```

交通、住宿、超时和额外稿件不含在基础价格内，须在接单前单独确认。写手不承担媒体邀请，也不决定媒体是否报道。

### 5.3 媒体邀请流程

媒体邀请可以从活动简报开始，不强制要求已有定稿。系统记录目标媒体、联系人、邀约时间、回复、到场意向、材料缺口和备选对象。

稿件互斥仅在双方明确约定独家、首发或禁发期时启用。锁定必须绑定稿件版本、开始时间和结束时间，并支持到期自动释放。

### 5.4 直编发稿流程

直编发稿必须绑定客户已确认的稿件版本、有效报价和渠道发布规则。报价在计划明细中保存快照；后续调价不影响已确认计划和历史订单。

### 5.5 新闻发布会流程

新闻发布会创建独立项目清单，至少覆盖：议题与口径、议程与嘉宾、场地与会务、媒体名单、新闻资料包、现场媒体接待、现场采写、会后发稿、成果归档。云采写、媒体邀请和直编发稿作为可选子服务分别确认。

### 5.6 供应商订单流程

```text
客户确认直编发布计划
→ 生成客户可见的发布任务
→ 平台按渠道执行关系生成供应商订单
→ 平台提交上游并记录外部单号
→ 接单、执行、异常或完成
→ 核验发布结果
→ 客户侧任务继续按云发布统一口径展示
```

供应商名称、联系人、采购成本、外部单号和异常处理记录只对平台运营开放。上游标记完成不能代替结果链接核验，也不能直接把客户任务标记为已交付。

## 6. 状态模型

### 6.1 发布计划

当前实现：`DRAFT / WAITING_CONFIRMATION → EXECUTING → COMPLETED`

可选终态：`CANCELLED`。只有 `WAITING_CONFIRMATION` 可以由客户确认；确认后不可直接修改稿件版本和价格快照。`CONFIRMED` 作为兼容状态保留，不是当前接口的停留状态。

### 6.2 计划明细

当前实现：`DRAFT → CONFIRMED → TASK_CREATED`，后续执行状态由关联的 `publish_task` 管理。

可选终态：`CANCELLED`。规则校验失败直接返回业务错误，不伪造一条已成功进入计划的记录。

### 6.3 写手派单

当前实现：`WAITING_MATCH → OFFERED → ACCEPTED → COMPLETED`

分支状态：`DECLINED`、`CANCELLED`。写手拒单后可由平台运营重新派给其他可用写手；现场执行和稿件交付继续由 `editorial_task`、`manuscript` 和稿件版本状态记录。

### 6.4 媒体邀请

`CANDIDATE → READY_TO_INVITE → INVITED → RESPONDED → ATTENDING / DECLINED / NOT_PROCEEDING`

媒体未回复、拒绝或未报道属于正常业务状态，不应被伪装成系统成功。

## 7. 权限与数据可见性

- 客户：仅查看自己组织的项目、客户服务价、公开渠道规则、公开执行状态和交付结果。
- 服务运营：查看被分配项目、稿件、执行规则、必要联系人和执行状态。
- 平台运营：查看全局项目、供应商、来源、成本、毛利、调价、权限、审计与结算。
- 写手型服务运营账号：通过 `writer_profile` 标记可接单范围，只查看派给自己的采写任务和被分配项目；不得查看媒体供应商、平台成本与其他客户项目。V4.1 复用 `PUBLISH_OPERATOR` 账号体系，不虚构一个尚未落库的独立角色。

公开接口不得返回：供应商名称、来源平台、采购成本、内部备注、密钥、原始接口载荷。

## 8. 官网信息架构

1. Header：产品级导航与两个主要动作。
2. Hero：一句产品定义，不承诺确定报道。
3. 任务入口：从客户当前状态开始。
4. 项目工作台：展示下一步、负责人、截止时间与异常。
5. 服务模块：媒体邀请、直编发稿、新闻发布会、云采写。
6. 媒体能力：区分媒体机构、联系人和直编发布产品。
7. 新闻发布会：展示专业项目清单。
8. 案例与信任：仅使用获授权案例；否则匿名或明确标记产品演示。
9. 最终行动：创建传播项目或咨询发布会。
10. 法律与信任：公开隐私政策、服务条款、服务边界、案例证据规则和联系入口；缺少可核验主体材料时明确标注待补，不虚构备案、电话或地址。

一级导航：`首页 / 服务方案 / 媒体资源 / 新闻发布会 / 客户案例 / 关于我们`。云采写保留为服务模块，不单独占用一级频道。

## 9. 文案准则

每个公开模块必须回答：适用于什么情况、客户需要提供什么、平台具体做什么、客户收到什么、哪些结果不能保证、下一步是什么。

禁止：赋能、生态、闭环、爆发、重塑、正确的故事、价值拉满等空泛词；禁止公开设计解释、内部规则、供应商来源和未经证明的数据。

## 10. P0 验收标准

- 发布计划可保存、读取、确认，确认前不创建任务，重复确认不重复创建任务。
- 云采写订单保存有效服务价格快照，并拥有派单、接单和拒单记录。
- 客户接口不返回供应商、原始来源和成本价。
- 成本价和客户价可以分别维护，并保留变化历史。
- 供应商、渠道关系、供应商订单和状态历史可由平台运营管理，客户侧无供应商与成本字段泄漏。
- API 接入只能提交商务咨询，不出现在普通服务下单选项中。
- 媒体邀请与直编发布不再使用同一套客户选择逻辑。
- 首页在 30 秒内能让新客户说出四项服务和下一步操作。
- 未授权品牌不得作为真实客户案例公开呈现。
- 桌面、平板、移动端无横向溢出；导航、弹窗、表格和按钮可键盘操作。
- 构建成功不能替代运行验收；后端、数据库、Redis和角色路径必须提供实际证据。
