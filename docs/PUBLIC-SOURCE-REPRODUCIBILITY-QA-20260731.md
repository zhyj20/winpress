# GitHub 公开源码可复现性 QA（2026-07-31）

## 结论

公开镜像与受控本机演示现在使用同一套数据库初始化和迁移脚本，但不再要求公开仓库携带媒体目录、报价或测试账号文件。公开模式只验证结构与导入路径；受控本机模式才会核对已批准输入的完整性。两种模式都不构成外部媒体授权、实时检索、供应商履约或生产验收。

## 修复的问题

此前 `docker-compose.local-demo.yml` 已安全地默认使用仅含表头的 CSV 样例，但 `verify-clean-local-db.ps1` 与 `verify-cold-start.ps1` 仍硬编码读取未公开的 `media_channels.csv`、`media_quotes.csv`，并把 2 万余行静态数据视为必要条件；`verify-clean-local-db.ps1` 还强制读取未公开的测试账号文档。公开 GitHub 克隆因此无法完成自身声明的结构验收。

## 已实施控制

- 新增 `scripts/lib/MediaSeedInputs.ps1`，优先级为显式参数、受控环境变量、受控本机文件、公开表头样例；渠道与报价必须成对提供。
- `verify-clean-local-db.ps1` 与 `verify-cold-start.ps1` 共同输出 `PUBLIC_HEADERS_ONLY` 或 `LOCAL_MEDIA_INPUT`，不会把两种输入混淆。
- 公开样例模式保留种子中的最小结构夹具，并验证导入、迁移、完整性约束和四项服务结构；不会伪造 2 万余条媒体或报价。
- 测试账号文档只有在受控工作区实际存在时才校验 bcrypt 哈希；公开结构回归可以显式使用 `-SkipAccountHashVerification`。
- 本机重建入口在两个环境变量均未设置、且受控本机 CSV 实际存在时才临时显式选择它们；调用结束后恢复调用进程的原环境变量。单边配置会直接拒绝。

## 仍不在本次结论内

- 正式媒体数据授权、数据范围、令牌、限流、沙箱和实时联调；
- 供应商真实报价、下单、回执、对账、重试与服务等级；
- 公司主体、案例授权、隐私/服务条款、域名、TLS、监控和生产灾备；
- 历史 `WRITING_AND_PUBLISHING` 记录的业务映射、迁移或归档决定。

上述事项仍须按照有效 PRD 的书面确认和生产预发布证据执行，不能以本机静态输入或公开样例替代。
