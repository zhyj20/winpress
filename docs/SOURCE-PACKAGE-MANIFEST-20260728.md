## 使用边界

- 本机演示编排含本地演示数据，只能用于隔离测试；其后端 JAR 由 `scripts/prepare-local-docker-backend.ps1` 在本机临时副本中重新测试和打包，生成物不随源码包交付。生产应使用 `docker-compose.production.yml` 与受保护的环境变量。
- 外部媒体数据、供应商履约、法律信息和生产凭据均未包含为“已验收能力”；生产 Compose 不会自动加载静态媒体目录、报价或演示供应商，以审查记录的待确认项为准。
- 人工媒体邀请名单仅能以“待项目核验”进入计划和任务记录；归档中的迁移 21 不会让名单自动绑定渠道、生成供应商订单、确认价格或宣称已邀请媒体。
- 迁移 22 仅修复被问号替换的服务受理标题并建立完整性约束；不会推测历史媒体、渠道、供应商、成本或报价。
- 本机测试账号凭据不随包交付；受控工作区中的回归辅助脚本会按账号说明的“快速登录”与“品牌案例”两种表格语义读取本机演示凭据，不能替代生产账号管理。
- 前端仅在本机演示编排注入 `VITE_LOCAL_DEMO=true` 时显示环境提示；生产 Compose 显式编译为 `false`，并由生产数据边界脚本校验。该提示只说明本机数据性质，不包含供应商、成本、上游接口、令牌或内部规则。
- 源码包包含 `scripts/verify-local-database-backup-restore.ps1`。该脚本只接受当前项目的本机演示 PostgreSQL 容器，把临时备份恢复到无宿主机端口、无持久化数据卷的隔离容器并自动清理；不包含上传文件恢复，也不能作为生产恢复验收。
- 源码包包含 `scripts/verify-local-upload-backup-restore.ps1`。该脚本只接受当前本机演示后端挂载的上传卷，把归档恢复到隔离临时卷后比较文件哈希、所有者、权限、大小和目录集合；不打印文件名或内容，不能替代生产加密、异地副本和恢复时限验收。
