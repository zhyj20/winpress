## 发现与修复

### 1. 供应商订单按任务号查不到

**复现：** 管理员订单列表显示 `taskNo`，但以该任务号作为 `keyword` 查询 `/admin/supplier-orders` 时，刚创建的直编发稿供应商订单不返回。

**根因：** `WorkflowRepository.supplierOrders` 与 `supplierOrdersCount` 的关键词条件只覆盖供应商订单号、外部订单号、项目名称、渠道名称和供应商名称，漏掉已向管理员展示的任务编号。

**修复：** 两个查询现在使用同一组检索字段：供应商订单号、外部订单号、任务号、计划号、项目号、项目名称、渠道名称和供应商名称。总数查询补齐计划关联，避免列表与分页总数口径不同。

### 2. 管理员订单深链与操作线索未对齐

**复现：** 访问 `/admin/suppliers?tab=orders` 仍会打开默认“供应商”页；订单列表首列不展示任务/计划编号，检索框也没有提示可用的业务编号。

**修复：** 三个子页与 `tab` 查询参数双向同步，订单深链可直接进入“供应商订单”；列表首列同时展示订单、任务、计划和项目编号，检索提示与实际后端检索字段一致。专项 Playwright 回归固定验证深链、按任务号筛选、桌面与移动端布局。

### 3. 供应商状态机回归场景选择错误

**复现：** 客户可下单渠道可以暂未分配供应商。该场景会创建 `PENDING_SUBMISSION / UNCONFIRMED` 的内部控制记录，这是正确行为，但旧脚本错误要求它已有供应商，继而把“待分配”误判为失败。

**修复：** 供应商状态机回归明确从管理员报价中选择“活动报价 + 活动渠道 + 内部供应商映射”的本机演示渠道。该路径只验证受控人工凭据的订单状态迁移，不表示任何真实供应商已被提交或已履约。

### 4. 采写名额状态断言过度

**复现：** 多写手采写订单的接口只返回本名额 `memberStatus`，旧脚本却断言整单 `status` 为 `OFFERED` / `ACCEPTED`。

**修复：** 回归改为验证 `memberStatus` 且确认接口不伪造整单状态，避免把一名写手响应误写为整个采写订单已满额。

### 5. 供应商订单分配候选没有按渠道收窄

**复现：** 后端保存供应商订单时会校验“供应商是否已关联当前渠道”，但订单处理弹窗使用全量可用供应商选项。运营人员可能在界面选中一个活跃、却未关联当前渠道的供应商，提交后才收到拒绝，形成一次无效操作。

**根因：** `/admin/suppliers/options` 只有全局候选语义；订单列表没有向前端提供渠道主键，前端也没有在打开订单时按渠道请求候选集。

**修复：** 管理员接口支持可选 `channelId`。带该参数时，查询只返回状态为 `ACTIVE` 且在 `supplier_channel` 中与当前渠道存在 `ACTIVE` 关联的供应商，并按关联优先级排序；无参数调用保持原有全局候选语义，供后台其他配置表单使用。供应商订单列表现在返回其内部 `channelId`，订单弹窗据此加载候选；加载失败、无关联和当前记录已失效均有明确的后台提示。客户和服务运营角色仍被接口拒绝，客户页面没有新增任何供应商字段。
