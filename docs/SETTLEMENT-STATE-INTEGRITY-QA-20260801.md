# 结算状态完整性与移动端可读性 QA（2026-08-01）

## 问题与影响

管理员结算页曾在任意状态下展示全部状态选项，而后端的人工更新接口没有限制直接转换。已取消或已结清的结算单因此可能被手工回退为“已确认”，造成台账状态与实际交易事实不一致。移动端宽表还需要横向滚动，客户／项目等关键字段不能一次完整阅读。

## 修复

- 后端仅允许：`PENDING → CONFIRMED/CANCELLED`、`CONFIRMED → PAID/CANCELLED`，以及保存原状态；`PAID` 与 `CANCELLED` 不能被人工状态更新重新开启。
- 前端以接口加载时的已持久化状态为准，只列出可直接进入的状态。用户在未保存前改变下拉框，不会因此获得额外状态选项。
- 小于等于 560px 时，结算宽表转换为逐项信息卡；金额、账务、状态和操作均保留，`.table-wrap` 不再出现内部横向滚动。
- `scripts/rebuild-local-demo.ps1` 在容器健康后执行 `scripts/verify-local-demo-runtime-artifact.ps1`；后者比较 `backend/target-local` 与容器 `/app/app.jar` 的 SHA-256，防止源码测试结果和运行镜像不一致。

## 数据与回滚边界

本项没有执行数据库迁移、自动拆单、历史组合服务处理、真实供应商下单或外部媒体检索。运行时回退请求被拒绝，未写入结算单。若需要回退，仅回退状态机代码、前端选择器、样式、测试与本机重建校验脚本；不得以此覆盖现有本机或生产业务数据。
