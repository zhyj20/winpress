## 一、产品收敛结论

云发布应是企业新闻传播项目的操作执行系统，而非媒体黄页、供应商门户或泛化服务商城。有效 PRD 定义的客户日常服务只有四项：

| 服务 | 服务代码 | 独立边界 |
|---|---|---|
| 现场采写 | `ONSITE_WRITING` | 内容采写、资料梳理、稿件撰写与修改；不承诺或替代媒体采访。 |
| 媒体邀请 | `MEDIA_PR` | 形成拟邀名单与邀请执行；媒体是否出席、采访或报道由媒体自主决定。 |
| 直编发稿 | `DIRECT_PUBLISHING` | 客户确认稿件后按选定渠道执行发布计划；稿件来源必须可追溯。 |
| 新闻发布会 | `NEWS_CONFERENCE` | 管理会前、现场、会后项目清单；需要采写、邀请或发稿时分别创建独立服务。 |

API 接入是商务和技术合作评估，必须先沟通授权、字段、价格、额度和验收方案，不能作为普通服务类型下单。活动关联只负责把独立项目放入同一活动视图，不能生成组合服务、组合价格或合并订单。

## 三、本轮 P0/P1 修复及证据

### P0：可用性、权限、数据边界

1. **附件不再经公开静态路径暴露。** 上传绑定项目，下载需认证并核验项目范围；`/files/` 与公开测试账号路径在前端网关拒绝。
2. **客户投影实行字段白名单。** 客户的项目、工作项、任务记录、订单台账、发布计划和媒体候选响应均由正向字段清单生成，不含供应商、成本、上游原始媒体/记者 ID、令牌、存储键、内部备注或操作人信息。
3. **渠道目录不再泄露内部标识。** 客户 `/channels` 响应移除平台渠道编号和报价主键；页面将目录、报价和排期明确为项目核验前的方案参考。
4. **角色范围收紧。** 客户不能读取写手派单；运营不能枚举客户需求；未分配运营不能读取客户项目。
5. **后台计价与供应商仅限平台管理员。** 客户与发布运营对报价、报价汇总、供应商和供应商订单接口均会被拒绝；成本、供应商关系、内部结算和操作日志不能经客户接口或页面返回。
6. **外部接口状态安全。** 媒体发现不向客户暴露重试、限流、冷却、供应商或令牌细节；第三方运行提示也不透传。候选资料只可表述为待项目核验，不能表示受邀、出席或报道已确认；没有正式配置时只能表示暂不可用。
7. **演示与生产分离。** 本机演示使用 `docker-compose.local-demo.yml`；生产编排要求显式环境变量，且本轮只做静态解析，不启动生产容器。
8. **健康状态与实际结构绑定。** `/health` 只会在当前数据库通过四服务闭环、人工媒体名单待核验及受理任务标题完整性所需的关键结构检查时报告 `schemaStatus=UP` 与版本 `22`；结构未就绪时返回通用升级状态，不泄露表名、迁移号或内部部署信息。
9. **人工名单不借用未验收渠道。** 客户补充的媒体或记者名单以空执行渠道保存，先进入项目核验；不得将其绑定到任意静态渠道、供应商、报价或外部目录记录，也不得自动写入“已邀请”。

### P1：流程、协同与跨端效率

1. 增加迁移 `18-service-intake-tasks.sql`，使媒体邀请与直编发稿拥有可追溯的受理任务。
2. 增加迁移 `19-activity-project-linkage.sql`，让新闻发布会可以关联同一活动下的独立服务项目，且不形成组合订单。
3. 增加迁移 `20-direct-manuscript-source.sql`，建立稿件来源版本关联，直编发稿复用已确认稿件时复制内容而不改动原项目。
4. 移动端操作台改为单一频道顶栏，侧栏由顶栏打开，关闭按钮和遮罩均可关闭，避免双层导航遮挡表单。
5. 新闻发布会表单保持“标题、联系人、联系电话”三项必填；媒体筛选不可用时保留人工补充路径，而不是展示虚构候选。
6. 保留客户可读的深链接兼容路径：`/requirements/onsite-writing` 打开云采写下单，`/task-records` 打开任务记录，避免旧书签或外部消息链接误落到营销首页；两条路径沿用原页面的客户权限与数据投影，不新增服务或放宽权限。
7. 客户台账不再沿用内部协同话术：内部状态 `PENDING_ASSIGNMENT` 显示为“待平台安排”，任务管理空状态不再把平台工单表述为客户可见事项；订单管理、任务管理和任务记录均只保留客户可核验的项目、服务、金额、状态、时间与说明。

- **审查发现：** 后端的 Spring 转发头处理会根据 `X-Forwarded-For` 识别登录失败限流来源，而前端代理原先使用追加式转发，允许客户端自带的转发链继续进入后端。攻击者可能借此伪造来源，削弱失败次数控制。
