# 供应商履约闭环 QA 记录（2026-07-31）

## 结论

本轮完成了直编发稿供应商订单的本机闭环修补：已关联供应商的任务不能绕过供应商履约直接向客户提交成果；异常重试不会复用上一轮的上游订单号或凭据；平台管理员可追溯完整状态轨迹。该结论仅适用于当前源码与本机隔离演示栈，不表示任何外部供应商已经真实接通或完成履约验收。

## 问题与影响

1. 异常订单退回 `PENDING_SUBMISSION` 时，旧的订单号、凭据、提交说明和时间可能继续留在当前记录，容易把上一轮尝试误当成新一轮已提交事实。
2. 已绑定供应商的直编任务可以在供应商订单尚未完成时直接登记成果，客户侧可能先看到“完成”，而内部履约并未闭合。
3. 数据库中已有状态历史，但管理员没有受控读取入口；清理当前重试上下文后，运营人员难以直接核对前一轮状态。

## 修补内容

| 范围 | 修补 |
|---|---|
| 状态重试 | 回到 `PENDING_SUBMISSION` 时强制使用 `UNCONFIRMED`，并拒绝携带上轮上游订单号、履约凭据或提交上下文。当前记录会清空该轮数据，状态历史保留说明。 |
| 履约方式 | 只有 `API` 履约方式可记录上游订单号；人工履约只登记受控凭据位置。 |
| 成果门禁 | 直编任务若已关联供应商，只有供应商订单为 `COMPLETED` 且具有履约凭据时，才允许运营人员提交客户可见成果。未关联供应商或未分配供应商的任务不被这一门禁误拦截。 |
| 管理员追溯 | 新增 `GET /api/v1/admin/supplier-orders/{supplierOrderId}/history`，仅 `PLATFORM_ADMIN` 可读取状态、时间、操作人和受控说明。客户与发布运营无权访问。 |
| 前端操作 | 管理员供应商订单弹窗展示状态轨迹；选择“待提交”自动清理当前履约填写项；非接口履约不展示上游订单号输入；各必填标识与字段标题使用同一标签组，移动端不再单独换行。 |

在上述材料完成前，页面与接口只能呈现“待确认”或人工核验路径，不能宣称实时供应商履约能力已经上线。

## 回退边界

本轮未改写任何历史业务记录，也未自动迁移或拆分组合服务。若后续业务政策调整，可回退应用层的状态与成果门禁实现；已形成的管理员状态历史应保留，不应通过删除记录掩盖既往履约尝试。
