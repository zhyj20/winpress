# 新闻发布会统筹事项状态完整性 QA

日期：2026-07-31  
环境：本机 Docker 演示栈（前端 `5217`、后端 `8192`、PostgreSQL `55434`）  
范围：新闻发布会项目统筹事项的状态迁移、并发保护、完成时间、前端操作约束、数据库迁移和本机回归。  

## 缺陷与影响

此前，已完成的统筹事项可以再次改为进行中或待处理；接口也没有携带客户端所见的当前状态。并发操作时，后提交的请求可能覆盖先提交的结果，且完成事项的 `completed_at` 可以为空。该问题会让项目清单的完成记录失去可核验性。

## 修复内容

1. 新增迁移 `40-conference-work-item-state-integrity.sql`，为统筹事项补充完成时间约束、终态保护触发器和项目完成一致性触发器。
2. 服务端更新接口要求提交 `expectedStatus`，在事务中锁定事项；状态已变化时返回 `409 CONFERENCE_WORK_ITEM_STATE_CHANGED`，已完成事项返回 `409 CONFERENCE_WORK_ITEM_FINALIZED`。
3. 只允许合法的前向状态迁移：待处理、进行中、待补充、受阻可在受控范围内继续推进或完成；`COMPLETED` 为终态，不能重新打开。标记“待补充”或“受阻”时必须留下说明。
4. 前端根据当前状态只显示可选动作；完成事项只读显示“事项已完成，状态已锁定”，不会再提交修改请求。
5. 新增桌面端和移动端端到端回归：完成事项所在卡片必须没有状态下拉框和“保存事项”按钮。
6. 同时修复该工作台暴露出的可访问性缺陷：隐藏上传控件具备可访问名称，项目摘要、关联订单、阶段进度、负责人、文件元信息和空状态文字均达到可读对比度。
7. 本机演示库中发现一条既有种子夹具为 `COMPLETED` 但缺少完成时间。迁移预检先拒绝执行；在迁移前备份后，仅为该一条可识别的本机演示夹具补回其已有 `updated_at` 对应的完成时间，再执行迁移。该处理不是生产历史修复方案，也没有推断、拆分、删除或改写其他业务事实。
8. 前端入口文档和 SPA 回退页改为不缓存，哈希静态资源保持长期缓存，避免容器重建期间旧入口页指向已替换资源而出现短暂空白页。
